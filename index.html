Tutorial on Remote Login, Module Loading, and Job Submission with Slurm

Five steps from your first login to a GPU job running on the server.

Prerequisites

  • The SSH client is installed on your local machine.
  • Access to a remote server with Slurm and module tools installed.
  • A prepared job script (or familiarity with creating one).
  • To upload/create/view/modify files, it is recommended to use FinalShell or FileZilla.
Connecting with FileZilla

Use Host sftp://hostname, Username username, your server password, and Port 22, then click Quickconnect.

Step 1: Log in to the Remote Server

To log in via SSH:

  1. Open a Terminal on your local machine.

    Windows

    Press Win, type Terminal (Windows 11) or PowerShell (Windows 10) and press Enter. Both already include the ssh command.

    macOS

    Press ⌘ Space, type Terminal and press Return.

    Linux

    Open your terminal app. On many desktops, Ctrl Alt T opens one.

  2. Run the SSH command:

    ssh username@hostname
    • Replace username with your remote server username.
    • Replace hostname with the IP address or domain name of the server.

    Example:

    ssh user123@cluster.example.com

  3. Authenticate by entering your password if prompted. A list of allowed commands will be displayed after login.

    • Your password stays invisible while you type. That's normal, so just press Enter when you're done.
    • The first time you connect, SSH asks you to confirm the server's fingerprint. Type yes and press Enter.

Step 2: Load Required Modules

Modules provide access to specific software or libraries on a shared server (currently, only Anaconda is installed with the latest PyTorch and TensorFlow). You can also install packages with pip and create your Python environment with conda.

Listing and loading modules:

  1. List available modules:

    module avail

    This command displays all modules available for loading on the server.

  2. Load a module:

    module load modulename

    Replace modulename with the desired module name.

    Example:

    module load anaconda

  3. Verify loaded modules:

    module list

    Shows the list of modules currently loaded in your session.

Step 3: Prepare a Slurm Job Script

There are two ways to submit jobs to Slurm.

Method 1 · Interactive Run a Python script with srun and watch its output live in your terminal. Method 2 · Job script Write a job script and submit it with sbatch. It keeps running after you log out. Steps 4 and 5 use this method.

Method 1: Run a Python script interactively

From terminal,

srun --gres=gpu:1 --time=00:30:00 --mem=500M python my_script.py

Information:

--gres=gpu:1
Specifies 1 GPU.
--time=00:30:00
Sets a 30-minute runtime limit.
--mem=500M
Allocates 500MB of memory.

This will run my_script.py and display output directly in the terminal.

Method 2: Submit a job script

To submit a python script to Slurm, you need a job script with specific configurations and commands. Below is a guide for creating a basic Slurm job script.

  1. Create and open a script file using Vim or other editors (if using Vim, press i to start editing):

    vim my_job_script.sh

  2. Add Slurm and command lines:

    #!/bin/bash
#SBATCH --job-name=my_job              # Job name
#SBATCH --output=output_%j.txt         # Output file name with job ID
#SBATCH --error=error_%j.txt           # Error file name with job ID
#SBATCH --gres=gpu:1                   # Number of GPUs

# Load necessary modules
module load anaconda

# Run the job command
python my_script.py

    You can also create the file on your computer and upload it with FinalShell or FileZilla. Want different resources? Build your own script.

  3. Save and close the editor.

    • If using Vim, press escape (Esc), type :wq, and press Enter to save and exit.

Step 4: Submit the Job to Slurm

To submit the job

sbatch my_job_script.sh

This submits the job to Slurm, which will schedule and execute it based on resource availability and job priority. Slurm replies with Submitted batch job <job_id>. Note the number.

To check job status

squeue -u username

Replace username with your actual username. This command shows the status of your jobs.

In the ST column, PD means pending (waiting for resources) and R means running. A job leaves the list once it finishes.

To view job output

After the job completes, check the output file specified in your script (e.g., output_<job_id>.txt) for results.

cat output_<job_id>.txt

Step 5: Monitor and Manage Jobs

Common job management commands:

Cancel a job

scancel <job_id>

Replace <job_id> with the ID of the job you want to cancel.

Note: Always confirm job parameters and resource requests as appropriate for your cluster's policies to avoid overloading shared resources.

Jupyter Notebook on the Server

Run Jupyter as a Slurm job on the GPU server and use it in the browser on your own computer, through an SSH tunnel.

Everyone on the server needs a different port. Use this number wherever PORT appears below.

Choose a number between 20000 and 29999 and use it wherever PORT appears below.

  1. Create a Jupyter job script

    On the server, create jupyter_job.sh (press i to edit; Esc then :wq to save):

    vim jupyter_job.sh

    Add these lines:

    #!/bin/bash
#SBATCH --job-name=jupyter             # Job name
#SBATCH --output=output.txt            # Jupyter log, including the URL and token
#SBATCH --gres=gpu:1                   # Number of GPUs
#SBATCH --time=02:00:00                # Time limit (2 h)
#SBATCH --mem=8G                       # Memory (8 GB)

# Load necessary modules
module load anaconda

# Start Jupyter on your port (reachable only through your SSH tunnel)
jupyter notebook --no-browser --ip=127.0.0.1 --port=PORT --port-retries=0

    There's deliberately no --error line. Jupyter prints its URL to the error stream, and without that line Slurm writes both streams to output.txt.

  2. Submit it and wait for it to start

    sbatch jupyter_job.sh
    squeue -u username

    Wait until the ST column shows R (running).

    Until the job starts, output.txt may still contain the URL from your previous session. Run these commands in the folder where you created the script.

  3. Open an SSH tunnel from your computer

    In a new terminal on your own computer, not on the server, run:

    ssh -N -L PORT:127.0.0.1:PORT username@hostname

    Enter your password. After that the window shows nothing, which is normal. Keep it open while you use Jupyter, and press Ctrl C to close the tunnel.

    What do -N and -L do?

    -L PORT:127.0.0.1:PORT forwards that port on your computer to the same port on the server, where Jupyter is listening. -N tells SSH not to open a shell, so it only keeps the tunnel open.

  4. Find the Jupyter URL and token

    Find the jupyter URL with token from output.txt file:

    cat output.txt

    Look for the line that starts with http://127.0.0.1:PORT/ and contains token=, and copy the whole URL.

  5. Open Jupyter in your browser

    Use jupyter notebook from your local machine as normal, with the computation performed on the server. Paste the URL into your browser. It works as-is, because the tunnel uses the same port on both ends.

When you're done: cancel the job so the GPU is free for others, then press Ctrl C in the tunnel window. Anyone with your token URL can run code as you, so never share it.

scancel <job_id>
Troubleshooting
port … is already in use or no available port could be found in output.txt
Someone else is using that port. Pick another port, update --port in jupyter_job.sh, and submit again.
bind … Address already in use when opening the tunnel
That port is busy on your own computer. Pick another port and use it in both the script and the tunnel.
channel … open failed: connect failed: Connection refused
Jupyter isn't running yet, or the port is wrong. Check squeue and output.txt.
administratively prohibited
Port forwarding isn't allowed for your account. Contact the server administrator.
